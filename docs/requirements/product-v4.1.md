## 1. 产品定位与服务边界

MSBOOST 面向 MapleStory 游戏场景，用户自行准备和管理 VPS。平台免费提供公告/教程、节点部署、在线 DD、自备中转的一次性配置；另提供本站增值线路中转、套餐时间和流量、余额卡密、订单、线路状态和流量查看。[S1 §2；S2；S6]

免费工具不要求购买本站套餐。套餐到期或流量用尽只影响本站增值转发权限，不取消免费工具和既有免费本机配置的下载能力。网站服务协议继续说明第三方 VPS、网络、游戏服务不由本站控制。

区分四种对象，避免权限和责任混淆：

| 对象 | 运行内容 | 管理方式 |
|---|---|---|
| 客户游戏节点 VPS | `msboost.service` | 客户自有；在线安装是一次性任务 |
| 客户免费中转/前置机 | 转发服务 | 一次性配置，不默认长期托管 |
| 本站中转服务器 | Go Agent + go-gost | 长期同步、监控、规则/额度管理 |
| 本站控制执行机 | 具备 executor 能力的 Go Agent | 接受受鉴权部署、DD、一次性中转任务 |

用户电脑上的 BAT + `msboost.exe` 是网站之外的客户端。网站提供说明与配置文件，不模拟/远程启动本机客户端，不增加“启动/停止/检查出口 IP”的网页版控制台。[S6 注册用户第1、16项]

## 2. 技术方向与模块结构

### 2.1 技术基础

继续以 S1 指定的 FLVX v2.2.0-alpha4 的 Go 后端、Go Agent、go-gost、TCP/UDP、通信与统计等能力作为二开方向，参考 relay-panel 的交互。**本次没有重新审计该 FLVX Tag，不宣称已完成上游代码迁入或功能兼容。** 新多级转跳的页面依据 I3，实际运行协议需开发验收。

建议：React + TypeScript + Vite，一个前端工程；Go 模块化单体 Server；Go Agent 按 executor/relay 能力授权；PostgreSQL 主存储。首期不把 Redis、Kafka、微服务作为前置条件。原稿 SQLite 兼容要求尚未明确撤销，保留在决策表中。

### 2.2 控制流程与游戏流量分开

```text
Web（同一个前端工程）
├─ 公开登录 / 注册
├─ 注册用户：公告教程、免费工具、任务记录、套餐与卡密
├─ 增值用户：以上能力 + 逐线路配置、状态和流量
└─ 管理员：用户、执行机、线路链、交易、内容、备份、系统设置
                │ HTTPS API / 状态流
Go Server
├─ 身份权限、业务限额、任务与脱敏审计
├─ 套餐、余额账本、卡密、订单、易支付适配
├─ 唯一目标、逐线路规则、多级链定义、流量与租约
└─ 公告附件、备份计划、设置与版本管理
                │ 鉴权 / 任务授权 / 配置版本 ACK
Go Agent
├─ executor：短期 SSH → 客户节点、免费中转、前置机、DD
└─ relay：go-gost 管理、本站链路、速率、流量、状态上报

客户端实际连接
电脑 → [客户前置机] → [本站入口 → 中间跳… → 出口] → 客户 MSBOOST 节点 → 游戏
```

游戏流量不经过 Web、业务 API 或 PostgreSQL。付款、登录、配置生成属于控制流程。executor 与 relay 令牌、可执行动作及网络范围必须隔离，普通中转 Agent 不自动获得 DD 权限。

## 4. 账号、角色与协议

### 4.1 账号规则

普通用户仍只接受纯数字 QQ 邮箱；规范化大小写并检查唯一性。管理员可以开关注册、要求邀请码；邀请码管理包括批量生成、查看、使用次数、使用人、时间、停用/删除。保留可选 Turnstile；SMTP 发信能力与注册/免费工具两项邮箱验证策略分别设置，详见 §4.5。注册、登录、任务创建与下载均需要后端权限校验。[S1 §4–5；S2-13]

基础角色只有管理员和普通用户，增值用户是普通用户的有效权益状态，不另增客服角色。管理员的部署与指纹限频豁免沿用原稿；其他豁免范围仍需确认。

### 4.3 隐私政策（沿用S6图片的五条文案）

1. 本站仅收集提供服务所必要的账号、任务、节点和使用记录。
2. SSH 用户名、密码等敏感信息仅用于当前任务处理，不作为普通业务数据长期保存。
3. 为安全审计，本站可能记录操作时间、服务器 IP、目标 IP/端口、任务结果及来源 IP，但不会在普通日志中记录密码、令牌等秘密信息。
4. 本站不会主动出售用户个人信息。
5. 用户应避免向本站提交与服务无关的个人敏感信息。

本机配置保存的用途、清理风险与手动删除操作在部署完成和任务页单独提示，不偷偷改写以上五条。上线前还需填明运营主体、联系方式、留存周期、必要第三方及用户删除申请路径；本次附件未给出，不编造。

两项是新增产品要求；下述处理细节是本补充稿的**实现约定/建议**，不修改其他付费规则。生产默认值未由用户指定。为不自动改变 v4 行为，UI 演示初始均关闭；管理员可以分别切换。原型内部使用对应 camelCase 字段。

#### 4.5.1 四种组合

- 用户记录保存 `email_verified_at`（未验证为 `null`），校验当前规范化邮箱与验证归属一致；邮箱发生变更时使原验证失效。

## 8. 配置自备中转

### 8.1 简化输入

上传 JSON → 填写**中转服务器地址**及 SSH 信息 → 确认 → 自动配置 → 下载配置。

删除“生成配置的中转入口（IP / 域名）”和“中转监听端口”两个输入。实际入口地址直接使用本次执行服务器 IP；监听端口由执行器/运行时确认未占用后随机分配。随机候选不等于占用保证，必须以真正绑定成功为准，冲突需重选。

中转服务器字段禁止域名，只接受允许的公网 IP。不能填带协议 URL、端口、私网或面板内部地址。这个明确限制针对用户填写的免费转发服务器地址；**不自动扩大为所有目标域名和管理员线路入口都永久禁止**。

默认每端口5 Mbps，用户不可调整。仍区分端口合计限速和单连接限速，最终 go-gost 字节单位换算须统一。

### 8.2 自备前置机：额外增加一跳，不替代中转机

本条已由 S7 注册第5项明确，第三版“前置机替代中转机”的解释撤销，不再列为待确认。[S7 第2页第5项、第3页纠错]

```text
不勾选前置机：
客户电脑 → 自备中转机 → MSBOOST 节点

勾选前置机：
客户电脑 → 客户自备前置机 → 自备中转机 → MSBOOST 节点
```

**界面要求**：中转服务器地址、SSH端口、用户名、密码始终显示、启用并必填。勾选“使用自备前置机”只新增第二组前置机信息，不隐藏、禁用、清空原中转服务器表单。两台服务器信息分别校验；取消勾选后前置机不参与本次任务。

**运行配置映射**：

| 模式 | 执行目标 | 转发目标 | 下载JSON的入口 |
|---|---|---|---|
| 无前置 | 自备中转机 | MSBOOST节点的IP/端口 | 自备中转机IP + 随机监听端口 |
| 有前置：中转段 | 自备中转机 | MSBOOST节点的IP/端口 | 不直接作为客户端入口 |
| 有前置：前置段 | 客户前置机 | **刚分配的自备中转机IP/监听端口** | 前置机IP + 前置随机监听端口 |

不能把前置段直接指向 MSBOOST 节点，否则会跳过中转机。两台机器的 SSH 端口与转发监听端口是不同字段；不要求用户手工选择监听端口。

**实现建议**：先配置并确认“中转机 → MSBOOST节点”，再配置“前置机 → 中转机”；保留两段任务阶段、IP和端口，任何一段失败都不显示整条链路成功。清理只针对本次任务创建的规则，不破坏已有服务。公网入站需另做验证，配置写入成功不等于游戏连接已成功。

原型会在任务详情显示两段 from/to，在导出配置写入前置机入口。原型暂要求前置机与中转机IP不同，避免把“双服务器”误配成同一机器；同机不同端口等特殊部署不是 S7 确认的范围，后续如需支持应单独定义。

### 8.3 JSON 转换

浏览器读取配置、确定唯一有效 profile/目标，保留认证用户名和密码；只替换客户端连接入口及端口，导出10086。多目标/多端口不可静默只取第一条；生产可提供明确选择或拒绝。本原型要求单 profile、单server、单port。

入口为 IP 时填 `ipAddress`、清空 `domainName`。认证展示名与真正认证字段分开；不因网站 QQ 邮箱不同而直接改 `user.name`。旧用户名迁移策略仍待确认。

生成的 `自备中转.json` 写到当前浏览器本地，与任务ID绑定；可从任务记录再下载。平台保留用户、IP/端口、结果等非秘密审计数据，不将免费 VPS 默认纳入常驻 Agent 托管。

终态提醒：**“已执行 DD 操作，请等待15分钟以上，再执行部署 MSBOOST。”** 不再默认展示“等待恢复验证”，不要求网站一直等待系统安装结束。

必须同时说明：“此状态仅表示操作已提交，不表示系统安装完成。”15分钟是用户要求的等待提示，不是完成时限或 SLA。

**实际验收判据建议**：安装准备步骤有成功返回，已发出预期重装/重启指令并记录提交阶段，随后发生预期连接中断，才可报“已执行”；仅 SSH 超时、密码错误或连接意外断开不能报已执行。提交是否成功不明确时显示“提交结果不明确”，不得盲目重试破坏性任务。后台可保留诊断记录，但不强制加回客户恢复等待页。

### 9.3 风险确认

执行前醒目提示“重装会清除原系统和数据”，保留一次明确确认。原稿指定删除的那条安全组强制勾选不重新加入；新端口可达性与云控制台救援作为文字提醒/教程提供。全站备份不代替客户 VPS 的磁盘备份。

## 10. 增值中转：逐线路配置与唯一目标

### 10.1 逐条操作

线路卡片显示名称、是否在线、是否要求前置机、参考状态、每端口速率及已配置状态；**每条线路点击“配置中转”后，均需为这条线路上传 JSON**。没有“上传一次自动开通全部线路”的入口。

弹窗或独立页包含三步：①上传此线路的配置；②可选或强制的客户自备国内前置机；③完整链路和参数确认。只有当前线路生成规则，其他线路仍“尚未配置”。已创建线路显示详情、暂停/恢复、删除及配置下载。

### 10.2 唯一目标规则仍然保留

S2 的“同一个付费客户只能转发一个 MSBOOST 配置，不同中转机也必须是同一配置”未被 S6 取消。逐线路上传改变的是操作方式，不是授权多个目标。

后端按用户记录一个当前目标版本；后续线路比较规范化目标地址、端口、协议及必要配置身份，不能只比较文件名。浏览器的目标摘要不是可信授权凭据，服务端仍需检查目标元数据、所有权和版本，不依赖前端阻止绕过。

不同目标必须走“更换统一目标”：显示受影响线路 → 撤销旧站内规则 → 确认可撤销状态/隔离失联节点 → 激活新目标 → 用户逐条重新配置。不能让旧目标保持运行并换文件名新增第二个目标。

### 10.3 客户国内前置机

```text
客户电脑 → [客户自备国内前置机] → 本站线路入口 → [中间跳…] → 本站出口 → 客户MSBOOST节点
```

管理员可按线路强制前置机；强制时客户不能取消，必须填写前置机 IP、SSH 端口、用户名、密码并核对指纹。可选时默认不勾选。前置监听端口自动分配，SSH凭据只用于当前配置任务。

带前置机时，下载配置的实际入口必须是前置机IP和其分配端口；不带前置机时使用本站线路入口。不能误填本站出口或客户原始目标。文件仍保留目标节点认证，客户端无需知道内部中间跳。

### 10.4 增值配置保存：服务器持久保存，用户到期后删除

**明确要求**：增值业务转发的完整客户端配置保存到服务器；用户在套餐有效期内登录网站，可随时重新下载已配置线路的文件，不依赖生成配置时的浏览器缓存。用户到期后删除该用户的服务器配置文件和本站转发。[S7 增值1]

本条替换第三版“增值完整配置也仅保存在本机”的建议。免费工具仍按第11章在浏览器本地保存，不因本条改为免费配置云端托管。

每条已创建的增值规则关联一份服务器配置对象，保存实际入口（有前置时是前置机）、端口、目标认证字段和配置格式版本。UI 提供“服务器保存”“从服务器下载”；换设备后登录同一账号也可下载。单条删除转发时，同步删除其服务器配置，不删除其他线路。

| 状态 | 下载 | 转发/文件处置 |
|---|---|---|
| 有效套餐、已配置线路 | 服务端鉴权后允许下载 | 文件持续保留，按规则授权转发 |
| 规则被暂停，用户未到期 | 仍可下载已有配置 | 暂停转发不等于删除文件 |
| 流量耗尽但尚未到期 | 本版暂允许下载已有文件 | 转发仍停止；S7只明确到期删除 |
| 用户到期 | 拒绝下载 | 删除该用户增值配置文件和本站转发 |
| 已到期后重新购买 | 已删除文件不自动复活 | 重新上传，逐条创建 |

上表中“流量耗尽但未到期”的下载行为是原型解释，不等于恢复流量授权；实际运营若也要求立即删除需另行确认。

### 10.5 到期清理的实现建议

后端以真实 `expires_at` 判断到期，不能仅以页面四舍五入的剩余天数为依据。到期时先撤销下载与创建授权，再发出规则撤销和配置删除任务。下载接口本身也检查到期，即使清理任务尚在执行，旧下载请求不能继续取到文件。

- 删除该账号所有本站线路规则、对应完整配置对象及其临时下载缓存；保留订单、财务流水、月流量和脱敏任务审计。
- 文件存储使用私有对象/数据库密文；下载经身份、对象所有权和权益检查，禁止公共目录直链；配置不写普通日志。
- 到期删除不能只移除文件列表而保留可下载URL。已签发下载链接的有效期不能越过到期时刻；撤销与失败重试可审计。
- 多级线路的入口、中间和出口运行时规则都纳入清理；离线Agent依靠租约到期停止，在线主动撤销。后台明确区分“业务授权已失效”“运行时已确认撤销”“待重试”，不把网络分区写成零延迟物理撤销。
- **无法远程擦除用户已下载的电脑文件，也不删除客户自建MSBOOST节点或自备服务器上的原始文件。** 停用本站转发足以令旧配置不能再借该本站入口使用。
- 配置包含认证密码，建议单独加密保存、密钥与数据分离；SSH密码仍是单次任务信息，不能跟客户端配置一起长期保存。

备份中的历史副本如何保留/清除要在生产隐私与备份策略中明确：到期必须删除在线业务存储，不能承诺历史离线备份也瞬间物理擦除；恢复历史备份时，必须先重做权益检查并删除已过期配置，不能复活过期转发。具体备份留存天数来源尚未给出。[实现建议，不补造留存期限]

### 10.6 转发认证边界与原型范围

普通端口透传不需要把MSBOOST目标认证密码交给所有中转Agent。此次保存完整文件是为了**产品要求的服务器再次下载**，不是因为GOST端口转发必须知道目标应用密码。中间跳自己的隧道认证与目标MSBOOST认证仍分开。[沿用第三版技术边界]

原型：完整增值配置存入独立的 `cloudConfigs` 模拟服务器区，不放入免费配置库；下载按钮检查模拟权益；“演示到期清理”删除模拟配置和规则。“恢复演示权益”仅用于反复体验，不自动恢复已删除配置。所有模拟数据实际仍在浏览器中；本次没有真实服务端、跨设备云端同步或后台清理服务。

## 11. 浏览器本地配置库与任务记录

### 11.1 用户可见行为（仅免费部署、自备中转）

完成部署/转发后保存本机副本，同时提供立即下载。再次登录同一网站、同一浏览器/浏览器配置文件时，任务列表按任务ID查找本机文件并显示：

| 状态 | 按钮 | 含义 |
|---|---|---|
| 已存当前浏览器 | 下载、删除本地 | 持久化成功且本机文件存在 |
| 仅本次可下载 | 下载 | 浏览器存储不可用，仅页面内存暂存 |
| 本机无文件 | 导入恢复 | 任务元数据可存在，但服务器不恢复完整配置 |
| DD任务 | 无配置下载 | DD不生成 MSBOOST 客户端 JSON |

同一个任务页还可列出增值任务，但其“配置存放”列显示“服务器保存 / 服务器配置已删除”，有效时提供“从服务器下载”，不提示用户导入浏览器备份才能下载。

删除本机配置不删除服务器转发、不删除任务审计；删除/暂停本站规则也不等同擦除用户已下载的文件。恢复时检查目标入口与任务绑定，防止把不相关文件误标成此任务配置。

文案：**“配置已保存在当前浏览器，请下载备份。清除网站数据或更换设备后，本机配置可能无法恢复。”** **免费配置**不能写“云端已保存”或“登录就能跨设备恢复”；增值服务器下载使用第10章单独文案。

### 11.2 实现建议与安全限制

使用 IndexedDB，不依赖 HTTP 缓存、Cookie 或 Service Worker 缓存保存秘密。建议保存加密配置及任务ID、用户隔离标识、格式版本；AES-GCM密钥由浏览器生成，不可导出 CryptoKey，同源IndexedDB保存。[R1–R2]

这不是端到端硬件保险箱：网站同源脚本仍有权调用密钥解密；XSS、恶意扩展、受控电脑或共享浏览器仍有风险。账号ID隔离只能防一般界面串号，不能将浏览器内的前端检查当作安全边界。生产需减少第三方脚本、执行 CSP、严格附件/Markdown 防XSS，提供退出时“清除本机配置”的自愿选项；更强保护可另评估独立本地解锁密码，但本次未默认增加。

浏览器存储与**协议、域名、端口**关联；站点换域名、HTTP换HTTPS、更换浏览器或配置文件都可能读不到原数据。无痕、存储配额、驱逐策略和用户主动清除都会影响留存。清理普通网页资源缓存不一定清除IndexedDB，真正清除网站数据才通常涉及它；产品不要保证“缓存还在就永久可恢复”。`navigator.storage.persist()` 可申请保留，但能否获准、是否被用户手动删除不由网站保证。[R2]

### 11.3 三处存储要说清楚

1. **客户自己的VPS**：运行节点必然保存服务端配置；当前脚本还生成 `/root/直连.json`。这不属于“本站云端保存”。
2. **MSBOOST平台服务器**：免费任务长期保存元数据，免费完整JSON仅在授权任务传递期短暂存在；增值完整JSON按第10章保存到期。两者均禁止普通日志打印，临时缓存与到期清理按类别处理。
3. **用户浏览器/下载目录**：客户端 JSON 含认证凭据。用户自行保管，可在本机再下载。

**免费**本机配置丢失且没有下载副本时，网站不应承诺自动恢复。用户拥有服务器权限时可能从自己的VPS找回或重新生成，但这必须是显式授权的新任务，不能静默连接服务器获取。

### 11.4 原型与生产区别

原型使用 IndexedDB保存演示元数据和免费加密配置；浏览器不支持时降级为内存并提示。增值模拟服务器区独立存完整演示JSON；这不是生产服务器加密实现，不得使用真实凭据测试。生产任务记录来自 API，本机仅补充下载可用状态；**原型所有记录也在本机，因此清除原型站点数据会连演示任务列表一起清除**，不代表生产服务端任务也会删除。

下载按钮应在用户点击时触发，避免依赖长任务后自动下载被浏览器拦截。加密及持久保存属于真实浏览器环境验收项目，不能仅凭生成HTML或看到“保存”标签就认定完成。

## 12. 管理员多级转跳线路

### 12.1 结构与界面 [I3；S6 后台第3项]

```text
线路
├─ 入口配置：入口节点、管理员设置的对外地址
├─ 转发链配置：0..N 个有顺序的中间跳
│  └─ 每跳：节点/候选节点池、协议、负载策略、连接IP
└─ 出口配置：节点/候选节点池、协议、负载策略、连接IP
```

提供“添加一跳”、删除、上移、下移，按顺序实时展示链路。入口/中间/出口必须分区，不把多个节点列表误解释成任意轮询全链。

I3 明确可见TCP、轮询和连接IP；本原型另外展示UDP、随机、主备顺序作为**候选交互**，不声称FLVX特定Tag已用相同算法/字段实现。正式协议枚举从实际 runtime 能力协商获取。

### 12.2 节点池与连接IP

负载策略只作用于同一跳的候选节点。多选节点时，显式连接IP候选应按所选节点的可用地址求有效交集；没有交集则仅允许“默认连接IP”，不得沿用上一组选中的失效IP。默认地址含义是由每个节点使用其已确认地址，不是空值随意连私网。

禁止空节点池、无效节点、循环/重复路径；没有中间跳且入口/出口相同，可以明确视为单节点直转，不误判循环。前置机属于客户链路，不被混入本站节点池。

### 12.3 配置版本与故障处理建议

保存链结构产生新版本，校验→分配端口→分发所需节点→收集ACK→激活入口。部分节点失败要回滚/清理临时规则，不能前端保存成功就宣称整链可用。删除线路检查用户关联规则；升级、回滚、暂停要明确已有连接和新连接影响。

主备切换不保证已有TCP游戏连接无损迁移；不能承诺多级转跳一定降低延迟。生产须测试协议对应关系、DNS、IPv6、多节点离线、超时、并发端口分配及链路环路。

### 12.4 计量建议

多级流量不要每跳各扣一遍套餐。建议每条用户规则固定入口或出口一个计费点，其他跳的指标用于诊断；这只是建议，计费方向、上下行、重传与单位由产品决策确定。跨线路共用用户套餐额度，不能给每个节点一份完整独立额度。

## 13. 套餐、卡密、余额与订单

### 13.1 删除说明卡，不删除业务

客户套餐页与后台套餐页删除“余额不是在线充值账户”整张提示卡。保留余额数字、兑换卡密、购买套餐和流水入口，使用普通易懂标题。

S6 没有明确要求新增在线充值。因此沿用 S2：**卡密只兑换余额；余额购买套餐；微信/支付宝直接购买套餐；不自动增加余额充值功能。** 若后续要改充值规则，应另行修改账本和支付用途。[S2-9；S6 增值第3项、后台第1项]

### 13.2 继承规则

套餐时间+流量，所有启用线路可选，不绑定等级线路。未被修改的1–31天、可0元、无生产默认套餐、方块选购、上下架及关联删除检查继续保留。再次购买条件是：**剩余时间<30天 OR 剩余流量<10GB**；两项都不小于阈值时才拒绝。首次购买不受已有剩余门槛阻挡。

新套餐暂沿用旧规则“覆盖剩余、不叠加”，付款前提示，不静默变成续时长累加。判断用真实剩余秒数和字节，不能使用四舍五入后的显示值。

到期/流量耗尽/用户暂停，停止本站规则；历史月流量保留，不能把“当前套餐已用重置”做成删除账本。用户可继续查看自己的订单和免费任务。

### 13.3 卡密管理：完整代码与批量操作

管理员的卡密列表**直接完整显示代码**，不使用 `***`、圆点或省略号遮挡代码，也不要求先点“查看”才能知道完整卡密。[S7 后台2]

列表保留卡密、面额、状态、批次/生成时间、使用用户、使用时间。提供搜索、状态筛选、复制、新增/批量生成、查看使用记录。复选框支持逐条选择和全选当前筛选结果；显示已选数量，未选择时批量按钮禁用。

批量功能包括启用、停用、导出所选、删除、清除选择；“导出全部”与“导出所选”明确区分。导出使用完整代码，不产生掩码码。已使用卡密不能通过重新启用再次兑换。

**删除处理建议 / 原型约定**：未使用码可从活动库删除；已使用码点击删除转为归档，保留兑换记录和余额账本，避免删除财务凭据。确认弹窗解释处理范围，归档可由筛选查看，不能把已兑金额扣回用户。

完整显示是管理员界面需求，不等于要求数据库明文保存。生产建议采用独立密钥加密的可恢复代码，加上兑换匹配摘要；已授权管理员列表读取后完整展示，普通用户和公开API无权枚举。列表访问、复制/导出与批量删除需权限和审计；不要沿用第三版“只在额外查看弹窗显示完整”的UI。[实现建议]

### 13.4 独立邀请码管理

邀请码管理为后台独立页面，详尽程度与卡密管理一致；系统设置中的“注册需邀请码”开关保留，并链接到此页面，而不是只放一个临时生成按钮。[S7 后台3]

| 字段 | 含义 |
|---|---|
| 完整邀请码 | 管理员可直接查看、复制、导出 |
| 批次/备注/生成时间 | 区分活动或生成批次 |
| 可使用次数 | **每一个码**允许被使用的总次数，可设置/编辑 |
| 已使用次数/剩余次数 | 与真实使用记录对应，不是生成数量 |
| 状态 | 可使用、已停用、已用完、已归档（归档为原型约定） |
| 使用记录 | 注册用户、使用时间；能查看同一码多次使用 |

批量生成分别填写“生成数量”和“每个码允许使用次数”。支持列表筛选、多选、批量启用/停用/导出/删除、单条编辑/复制/记录，不能把使用次数仅展示为静态文字。

注册要求邀请码时，后端检查代码存在、启用、未删除、剩余次数>0，并在同一注册事务中占用一次。并发注册不能超出上限；注册未成功不永久占用次数；同一请求重试不重复消耗。停用不删已注册用户；提高次数可使已用完码重新可用，降低总次数不得小于已经使用的次数。

**原型约定**：生成数量示例5个、每码示例1次不是正式运营默认承诺。已使用码删除时归档保留记录；未使用码直接删除。邀请码和余额卡密分开，邀请码不增加余额或套餐。

### 13.5 账本规则不变

余额用最小货币单位整数；管理员调整记录原因；购买扣余额、订单与权益更新在事务中原子完成。回调、重试和多次点击不得重复扣款/发放。卡密仍只兑换余额，不能因为新增批量管理就改成兑换套餐。

## 14. 易支付 v1 / v2 配置

### 14.1 参考范围

按用户指定的独角兽支付指南 R4 和仓库适配器 R5 组织页面字段；**只参考支付渠道设计，不迁入其 Vue 前端、Redis依赖或整套电商系统**。本次读到的适配器提交为 `f06035ca359b0e4e99908fa6ae232af85e923d7f`，不是对用户实际支付供应商接口的验证。

### 14.2 后台字段

| 共用字段 | v1专用 | v2专用 |
|---|---|---|
| 渠道名称、启停、网关地址、商户ID | 商户密钥 `merchant_key` | 商户私钥 `private_key` |
| 协议版本、微信/支付宝类型 | 当前参考默认MD5 | 平台公钥 `platform_public_key` |
| 二维码/页面跳转交互 | API路径默认 `/mapi.php` | 当前参考默认RSA；API路径 `/api/pay/create` |
| 异步通知、同步返回、测试/诊断 | 跳转 `/submit.php` | 跳转 `/api/pay/submit` |

切换版本立即切换字段，v1密钥不能冒充v2密钥。已保存秘密不回显，留空表示不替换；切换版本时必须补全新版本密钥。统一网关可以建立两个支付类型渠道，但是否商户已开通微信或支付宝需要真实服务商确认。

UI显示的 `/api/payments/epay/{channel_id}/notify` 是MSBOOST拟定路由，不是声称照搬独角兽固定路径。正式地址由站点配置生成，需要HTTPS、回调可达和验证。

### 14.3 订单与验证

服务端创建订单并固定用户、套餐、金额、币种、权益版本。回调核验签名、商户归属、订单、金额、币种及支付成功状态后，幂等履约；同步跳转或前端“已支付”按钮不是到账依据。

同一用户多待支付订单、付款晚到、已到期订单、重复通知、退款和已扣款未发权益需可追踪处理，不无限覆盖新权益。异常款项和退款规则仍待运营确认，不擅自定“任何情况不退款”。原型没有真实二维码、网关请求或签名校验，只演示字段和订单状态。

## 15. 流量、监控与 Agent

### 15.1 Agent 管理补全

Agent 管理提供新增、**编辑、删除**、启停设置、诊断与安装命令。控制执行机与中转机仍分能力，不能因为统一Agent界面让中转机得到DD权限。[S7 后台1]

| 字段 | 控制执行机 | 中转机 |
|---|---|---|
| 名称、IP、启用状态、心跳状态 | 有 | 有 |
| 可用端口范围 | 不显示（不分配本站转发监听端口） | 可编辑，支持多段范围 |
| 是否强制客户使用前置机 | 不显示 | 可勾选 |
| 编辑、删除、诊断、安装命令 | 有 | 有 |

“可用端口范围”应校验1–65535、起止顺序、非法字符和范围重叠；生产要排除管理服务占用、执行真实端口预留/绑定并处理并发。演示默认范围20000–59999仅为模型值，不是 S7 指定的生产数值。缩小范围不能把正在使用的端口悄悄遗留成违规状态；原型拒绝这种修改并提示先迁移/删除关联规则。

**强制前置机的本版实现约定**：线路本身的要求与参与该线路的中转Agent要求合并，只要任一要求强制，则客户必须配置前置机；不能在客户表单取消。此约定用于把已有线路开关与 S7 新Agent开关衔接，来源没有规定其他覆盖优先级。

编辑已有节点时展示关联线路；把前置要求从可选改为强制，若现有用户规则缺前置机，不能静默当作满足要求。原型在编辑框明确提醒并暂停相关模拟规则，客户需要重新配置。生产迁移通知和生效时机为实现建议，须在上线前确认，不能无提示切断客户。

删除节点前检查线路、跳级与运行规则引用。原型对有引用节点显示关联线路并阻止删除；无引用节点二次确认后删除管理记录。删除管理记录不等于卸载远端Agent或抹除客户VPS，远端解绑/停服必须另有受控流程。删除后不影响已存在的脱敏任务审计。

### 15.2 流量、状态与运行时


后台仍需用户—线路—入口/目标端口—Agent—速率—流量—状态的独立用户中转视图。管理员可调整单用户本站速率；账户共享上限与每条规则上限的区别待确认。本原型按每条规则应用演示。

保留节点CPU、内存、磁盘、版本、运行时长、连接数、上/下行速率、累计流量及诊断。用户端只显示有权限的轻量状态；建议Agent上报一次，Server复用最近样本，页面按可见状态轮询，不让每个用户触发一次真实节点探测。

监控频率、指标留存和容量需压测，本次不承诺固定VPS配置可承载1000人。数据过期应标注最后上报时间，不把缓存旧数据写成实时。

规则失效采用在线主动撤销与离线短期租约相结合；网络分区时不承诺无条件零延迟撤销。规则版本、ACK、计数序号/启动周期去重，Agent重启不能重复扣费或清零用户用量。

## 16. 自动备份、远程目标与恢复

### 16.1 备份范围

“全站备份”是平台数据，不是客户VPS整盘。可选择：业务数据库；站点设置/版本清单；公告教程和附件；任务审计；流量监控历史；必要密钥的加密备份。**客户浏览器的免费本地配置不在全站备份内**；增值服务器配置属于受保护的平台业务数据，备份范围/密钥恢复需明确，恢复时排除已到期配置（见§10.5）。[S6 后台第4项]

完整快照必须记录选择范围和一致性要求。以“选择数据”提供UI，不等于可以任意截取几个数据库表后保证恢复一致。财务表、用户、权益和关联规则原则上作为一致性数据集合处理。

### 16.2 自动计划字段

| 类别 | 设置 |
|---|---|
| 开关 | 开启/暂停自动备份；关闭不删除已有备份 |
| 频率 | 每天指定时间；每隔N小时；每周指定日/时间 |
| 时区 | 默认建议Asia/Shanghai，明确显示，可设UTC |
| 范围 | 选择数据库、设置、附件、审计、指标、加密密钥 |
| 目标 | 本机暂存及一个或多个远程目标 |
| 保留 | 本机保留天数、每个远程目标保留天数、最少成功副本数 |
| 执行 | 超时、失败重试次数/退避、同一计划防重入 |
| 通知 | 失败提醒、可选成功提醒、连续失败/空间不足告警 |
| 结果 | 下一次执行、上次成功/失败、大小、版本、校验、目标上传状态 |

本原型时间、N小时、留存数值均为演示，不视作用户已确认运营参数；示例30天、至少3份、暂存7天可更改。后台应展示真正计算出的下一次时间，而非仅一个“自动”开关。

### 16.3 远程方式建议（用户允许补充）

**首期建议SFTP/SSH**：复用用户熟悉的服务器形式，使用备份专用账号/SSH密钥、固定目录、核对主机指纹、最小权限。长期平台备份密钥与客户一次性SSH密码不同，需要加密/secret管理，可轮换、测试连接/写入并记录结果。

**可选扩展S3兼容对象存储**：使用Endpoint、Bucket、前缀、区域/路径寻址配置及最小权限访问密钥；最终字段以选定驱动为准。是否使用对象锁/版本管理取决于实际服务商，UI不承诺所有提供方都支持。

**工具建议**：可评估restic用于加密、远程仓库、快照和保留策略；官方支持SFTP、S3，提供forget/prune等操作。[R6] 这是备份模块实现选项，不是新增系统必需服务，也不是本次已经接入。只做轻量备份时也可实现受控打包+SFTP，但必须自行补齐一致性、清单、加密与恢复校验。

### 16.4 自动流程与安全删除

```text
计划触发 → 防重入与空间检查 → 一致性导出 → 打包/加密/清单与哈希
→ 上传临时对象 → 校验远程完整性 → 确认为成功副本
→ 按目标执行保留清理 → 记录结果 / 通知
```

新副本失败时不删除最后的成功恢复点。超期判断同时满足“超保留天数”和“不是最少N份保护副本”，按目标分别统计。提供清理预览；失败/未校验副本不能冒充成功保护点。需要锁保护并发备份/清理，避免删除正在写入的文件。远程删除权限和数据不可逆影响要明确。

### 16.5 下载、上传与恢复

管理员可下载备份、上传旧备份、选择远程快照、查看格式/版本/哈希/范围/密钥要求。上传只进入隔离区，不能自动执行包内脚本或路径穿越写入。

恢复先预检与解密检查 → 备份当前站点 → 维护窗口/暂停写入与支付履约 → 明确覆盖范围 → 二次确认 → 恢复 → 自检 → 重新关联Agent/账本 → 恢复服务。失败保留回滚途径；不是点击“上传”就立即覆盖生产。

自动备份不等于自动恢复。定期进行恢复演练、记录恢复耗时与验证结果是建议，不擅自启用生产自动回滚。数据库恢复可能回退已付款状态，恢复后须对账，防止重复收款/发放或丢失真实支付权益。

密钥可恢复性必须独立考虑：密钥与密文全放同一位置不是充分保护；只有数据库没有密钥可能无法恢复支付/备份配置。需要独立的受控密钥备份与恢复文档，不向用户承诺“随便一个ZIP可无条件恢复全部服务”。


本地IndexedDB另存用户隔离标识、taskId、文件名、密文、随机IV、格式版本、加密密钥引用；不与平台数据库的SSH秘密混存。IP/端口/审计的生产留存期尚未给出，需明确并落实删除/访问控制。

### 18.2 API边界建议

`/api/tasks`受理任务；`/api/tasks/{id}`提供脱敏状态；短期配置交付通道单独鉴权并禁止缓存。`/api/routes`提供可用线路；`/api/user/routes/{route_id}/rules`只创建指定线路；`/api/user/target`管理统一目标版本。增值配置下载使用独立受鉴权接口，例如 `/api/user/routes/{route_id}/config`；服务端检查用户、当前规则和到期状态，不接受前端提交的用户ID作为授权。到期拒绝下载，不重定向到公共可下载文件。后台链定义、备份计划和支付配置使用独立管理员权限。

建议后台补齐Agent更新/删除、邀请码批量操作/使用记录、卡密批量操作、文章删除接口，操作对象列表要逐项检查权限和关联关系。批量操作不能绕过单条操作的限制。

这些是建议路由，不声称与FLVX现有接口完全一致。所有输入校验、对象所有权、次数、余额、权益与唯一目标均在服务端强制执行。随机ID不是权限验证。

### 18.3 生产安全验收

防SSRF必须覆盖SSH、目标地址、前置机、管理员远程备份和DNS变化；校验与实际拨号一致，规范化IPv4/IPv6，拒绝面板、容器网、回环、私网、链路本地、云元数据等未授权目标。原型只做基本地址格式与部分明显私网过滤，不是完整生产IP分类实现，也不能把示例保留网段当作生产允许列表。

安装、DD、订单和卡密幂等；HTTP401/403、证书、DNS、下载校验、系统包锁、NTP、Agent离线分别报告；避免执行日志含命令密码、完整JSON和秘密令牌。附件、Markdown、本机配置页的XSS安全直接影响配置安全，必须专项检查。

### 18.4 上线最低验收

| 领域 | 关键验收 |
|---|---|
| 登录 | 空邮箱初值、协议主动勾选、QQ校验、注册/邀请/验证开关、退出清会话 |
| 邮箱验证策略 | 两独立开关的四组合；免验证注册不标记已验证；旧账号补验证；错误/过期/重复码拒绝；改邮箱失效；后台状态正确 |
| 免费工具验证 | 服务端发起/重试/SSH预检门槛；拒绝不扣业务次数；增值用户使用免费工具不自动豁免；历史任务/下载不新增限制 |
