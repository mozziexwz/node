# 安全模型、已验证范围与交付差距

本工程包含真实业务事务、受限 SSH 执行、兑换签名和 GOST 转发代码。本文描述源码实现与安全边界；是否已发布、是否通过现场验收，须分别核对相应固定版本的 Release 资产、CI 和实际部署记录。不能把本地回归等同于正式制品或生产全功能验收。

## 身份与秘密

- 用户身份来自服务器会话，管理员接口再次检查角色；普通用户不能在请求中指定其他userId获得授权。会话使用HttpOnly Cookie；HTTPS站点启用Secure；写请求要求会话CSRF令牌并检查Origin。页面展示角色与隐藏按钮不是授权边界。
- 登录密码以 bcrypt 哈希持久化。注册、会员找回和管理员本机改密共用同一策略：至少 8 个字符且不超过 72 个 UTF-8 字节；不得等于完整邮箱或 `@` 前的邮箱前缀；不得包含连续 6 位或以上 ASCII 数字。普通及尚未验证邮箱的会员可通过注册邮箱找回，管理员禁止邮件找回。身份接口使用 safeUser 清除 PasswordHash；商务/线路接口没有直接序列化 User 对象，只返回所需的枫叶、兑换记录、流量和规则字段。不存在“回显原登录密码”功能。
- 持续保存的兑换渠道密钥、兑换码完整代码、捐赠权益客户端配置、备份目标专用私钥以及备份正文用服务器 AES-GCM 加密。完整兑换码只在管理员接口解密展示，列表读取、生成和批量导出/删除有审计。兑换匹配用独立 SHA256 摘要。
- 主密钥来自MASTER_KEY或首次生成的私有data/master.key。密钥与数据库同一主机时，不能防护取得该主机完整访问权的攻击者；生产应独立保护、备份密钥和数据库。工程没有接入外部KMS、HSM或多租户独立密钥体系。丢失主密钥后，现存加密配置和备份不能解密。
- 用户VPS SSH密码只在浏览器当前表单、HTTP请求和执行器内存任务中短暂存在；不能写入持久任务队列、数据库或普通日志。默认提交时真实探测并首次信任（TOFU），主机密钥按用户/IP/端口持久钉扎；后续变化拒绝，需通过控制台独立核实并显式替换。首次信任无法排除首次连接的中间人攻击，仍提供严格独立核对模式，执行连接绝不跳过主机密钥检查。免费本机文件与增值服务器文件是不同保存范围。
- 固定任务参数经过校验，executor不提供任意命令执行API；relay令牌与executor令牌分离，relay运行时没有SSH、DD或安装执行能力。管理员SFTP备份凭据是单独用途的长期专用私钥，不是保存客户一次性SSH密码。
- 免费工具清理要求相同用户/主机/端口/指纹的短期预览、清单摘要及二次确认；每份预览只能提交一次。远端重新校验固定路径、所有权、服务定义及清单摘要，拒绝符号链接、陌生文件和服务改写。保留备份、账户、依赖和共享缓存；不会全局清理 Docker、防火墙或第三方转发。失败或失联不自动重放，部分执行需先检查再重新预览。
- 任务诊断使用封闭错误代码及中文说明，远端任意 stdout/stderr 不能写入审计；没有证据时显示未能确定阶段原因，不能将所有 SSH 失败归咎于密码或将所有安装失败归咎于 CPU。DD 已提交重启不等于系统安装完成。

## 权益、枫叶与兑换

- 底层金额继续用整数分兼容既有数据库和渠道，但用户操作只允许整枫叶值（100 分的整数倍），页面不显示人民币符号或小数。枫叶扣减、账本、兑换记录和权益覆盖在同一数据库事务内完成。兑换码只兑换枫叶，不能直接兑换权益。权益允许 0 枫叶、1–31 天，无生产示例权益。
- 再次兑换按真实剩余时间和字节判断：剩余时间小于 30 天，或剩余流量小于十进制 10GB，即可兑换；两者均达到阈值才拒绝。兑换必须确认覆盖，时间和流量不叠加。权益用量重置不删除历史月流量。
- 兑换码和兑换记录有幂等键；已使用兑换码不能再启用，删除转归档且默认列表隐藏。相同 requestId 网络重试幂等；新 requestId 再次兑换已用代码只返回“兑换码无效或已被使用”，不泄露更多状态。本人流水读取时展示使用兑换码，管理员可按归档筛选查看使用邮箱和时间；明文不重新写入账本。批量操作仍逐项检查。
- 权益支持每用户兑换次数上限（0 无限），按历史已履约记录计次，免费、枫叶和全部在线渠道在事务内一致检查；幂等重试不扣次数。兑换邮箱验证开关开启时未验证用户不能下单，开关启用要求 SMTP 测试就绪。渠道通知时发现上限或邮箱条件已不满足会进入 `paid_review`，不丢弃已收到的款项。
- `currentHoldersOnly` 正常权益只允许当前权益未到期且当前权益 ID 与目标权益匹配的用户续兑；历史买过但已到期、当前持有其他权益或从未持有者均拒绝。`trial` 体验权益只允许从未履约过任何体验权益的用户兑换，同一用户终身合计一次且不能续兑。两项限制在同一交易事务内覆盖免费、枫叶和在线渠道；有效签名款项晚到且条件已变化时进入 `paid_review`，不能静默丢款或越权发放。
- 已实现易支付 v1 的 MD5 和 v2 的 RSA-SHA256 签名、真实收银台跳转、异步通知验签。异步通知核验商户、渠道、兑换编号、交易号、金额、币种约定和成功状态。已有通知不因销售或渠道开关关闭而丢弃。款项晚到、用户权益变化、维护期间付款进入 `paid_review` 留待对账，不覆盖新权益。同步回跳从不作为已付款依据。
- 已有兑换记录引用的商户身份和密钥不可覆盖；轮换须新建渠道，以保存旧通知验证能力。未配置 HTTPS PUBLIC_URL、真实商户或密钥时不能发起真实在线兑换；不会产生示例成功结果。
- **尚未交付**二维码统一下单API、主动查单、自动关单/退款、自动异常款处理和完整对账工具。当前paymentUrl只走v1 `/submit.php` 或v2 `/api/pay/submit`。实际供应商兼容性、微信/支付宝商户开通状态和公网回调仍需运营提供真实商户后验收。

## 中转与计量

- 管理界面按“节点→隧道”配置。端口转发仅有入口；隧道转发具有单入口、有序中间跳和出口候选池。候选策略只用于同一层，不把节点列表当成整链随机顺序。客户端与最终MSBOOST目标保持TCP，跳间可选TCP/TLS，负载策略为round/rand/fifo。重复节点和环路拒绝；旧单节点直转按端口转发兼容。
- 每条用户线路单独上传配置，服务端检查单profile、单server、单TCP端口。跨线路的规范化目标、端口、协议及认证用户名密码必须一致。更换统一目标先撤销全部旧规则；v1 等待最后租约失效，v2 必须逐段取得明确 revoke 停止证明。混合链路不能仅凭超时释放旧目标或端口。
- 节点级强制前置选项已取消，旧节点字段不再继承；仅保留隧道级自备前置要求。权益前置流程先准备本站真实绑定，再由 executor 把前置指向本站入口，最后将下载 JSON 入口替换为前置 IP 和端口。前置失败撤销本站规则；后台不能以填入任意 frontTaskId 绕过真实执行。前置 SSH 凭据不持久化；权益到期停止的是本站链路，自备前置机上的一次性软件不通过已丢弃的密码远程卸载。
- 普通用户的线路/状态/规则响应不返回入口地址、端口或运行segments；不是只隐藏页面文字。实际下载配置仍必须包含可连接的入口，不能保证授权下载者不知道其使用的地址。
- 权益与线路都使用 L1–L3 等级。用户只能选择不高于当前权益等级的线路；例如 L3 可用 L1/L2/L3，L1 不能使用 L2/L3。该判断由服务端执行，不能靠隐藏按钮作为授权边界。管理员的一键线路清理会撤销该线路上的全部客户规则，属于有审计的破坏性业务操作；执行前仍需核对精确线路。
- 线路卡片显示当前规则已用上行与下行流量：小于 1GB 按 MB、达到 1GB 按 GB，显示两位小数。一次性“诊断”通过当前隧道探测到 MSBOOST 目标，返回所测入口、成功/失败、延迟和丢包率；它是即时样本，不是持续可用性、游戏登录或全路径 SLA 证明。
- 线路显示顺序是服务端持久化的管理员自定义顺序，不依赖名称、在线心跳或无序集合遍历。权益流量重置会把该用户各线路规则的当前 `inputBytes` / `outputBytes` / 汇总值一并归零；历史月度计量和审计继续保留，旧 Agent 累计游标必须建立新基线，不能把重置前累计值重新扣回。
- 每条GOST规则独立子进程，使用固定配置、服务级字节速率和累计Observer。中间/出口仅允许上一层登记的源IP；带前置的入口仅允许前置源IP。节点支持登记多个IPv4/IPv6，跳间按自动/IPv4/IPv6偏好或共有显式连接IP选择，未登记相应地址会拒绝；不伪造网卡自动发现。节点实际出站源IP须与登记IP一致，NAT、多出口或多网卡场景需单独规划。应用目标认证不下发给中间Agent。
- 跳间 TLS 在目标 Relay Agent 的公网入口终止，随后对明文执行协议筛查，再交给仅监听回环地址的 GOST；前一跳继续以固定证书身份校验，最低 TLS 1.2，不跳过验证。每节点/规则独立证书和私钥只交付所属节点；证书一年有效，纯 v1 在剩余不足 7 天时自动轮换，含 v2 的链路普通重连不自动轮换，须经受保护维护操作，可能断开现有连接。证书过期不降低验证要求。当前使用源 IP 准入而非双向客户端证书认证。
- 免费自备中转与捐赠权益节点转发的每个公网 TCP 入口默认筛查可识别的明文 SOCKS4/5 握手，无用户开关；客户端本机供游戏使用的 SOCKS5 入口不受此限制。筛查发生在公网入口，TLS 跳间在解密后筛查；受管 GOST 仅监听回环地址，继续执行目标转发、速率与计量。为避免误伤开头含随机字节的游戏协议，检测只匹配常见握手形态；过长或经加密、封装、修改的 SOCKS 不能靠字节签名彻底识别，因此这不是抵御有意规避者的密码学保证。仍须使用固定目标、权益和用途限制，并以真实游戏连接与 SOCKS 拒绝测试共同验收。
- 用户域名目标在创建时解析，全部结果必须为公网地址，再将地址固定在规则中，避免后续DNS重绑定访问内网。公网域名/IP规则不等于拥有端到端可达性或游戏服务可用性。目标DNS变化需要重新配置。
- 服务端在事务中从允许范围随机分配不重复的端口，捐赠权益与免费自备中转配置都不按区间起点顺序递增。分配排除活动、待安全撤销及恢复保留的端口；真正绑定仍由 GOST 负责。端口被其他系统服务占用会报告失败，不显示转发成功。随机端口不是认证或防火墙替代；当前绑定冲突没有自动迁移整条链，应释放冲突端口或调整端口池后重新配置。缩减端口池、删除引用中的 Agent/线路会被拒绝。
- 下游有真实GOST监听ACK后才发布入口。Agent重启使旧ACK失效；没有绑定ACK不能显示active。active仅表示GOST进程监听准备完成，不保证公网入口、第三方网络、游戏认证或现有TCP会话无损。
- 全新 Relay 安装默认 v2 / keep_last：DNS/TLS/HTTP/认证故障保留最后配置，只有受信明确命令或本机/进程生命周期操作停止业务；失联期间新封禁、到期和超额决定会延后执行。显式 `--offline-policy lease` 兼容 v1，每 5 秒同步、最后授权租约 45 秒，独立 watchdog 到期停止 GOST，并扣除控制请求往返时间。既有节点不自动迁移；活动 lease 切换必须显式确认 Agent/GOST 重启风险。Linux 父进程死亡保护仍保留，Agent/节点升级重启不保证原 TCP 会话。完整契约见 [Relay v2](relay-v2-contract.md)。
- 计费点固定在入口，按隧道配置双向/仅上传/仅下载和 0.001–100 倍计量；费率随规则保存快照。倍率采用整数千分和持久化余数，分次上报不会截断丢失小数字节。十进制 GB，各线路共享用户额度，中间各跳不重复扣费。累计计数使用 Agent、规则、进程 epoch、单调 sequence 去重；已撤销规则保留无秘密的计量归属归档，旧权益迟到样本只保留历史，不扣新权益。
- Observer 样本每约 1 秒产生，断电可能丢失最后尚未产生/提交的短窗口计数。配额停止受同步可达性及协议模式影响，**不是精确到最后一字节的分布式硬配额**。v2 样本仅在数据库提交后的精确 ACK 才清除；旧权益按历史周期入账，不扣新权益。可信且不跨月的采集区间按原 UTC 月归属；跨月、时钟异常或无法细分的区间进入待核对，不伪造精确月份。v1 保留原接收月口径。v2 仅账务元数据变化不重启 GOST，实际速率改变仍可能重建连接。缓存有界，耗尽时明确 accounting_degraded 和缺口，保留既有业务并冻结新增。
- 当前速率是每条规则服务级、上下行分别限速，有效值为用户当前速率与线路上限的较小值。管理员改速率会更新该用户所有规则的各跳版本，逐跳新 ACK 到齐才显示已生效；旧 ACK 不得激活新版本。权益显示授予值，线路页显示当前及有效值，未实现跨所有线路共享的总速率调度。管理员可暂停/恢复/撤销全部用户规则；v2 撤销未获精确停止确认前持续保留资源，暂停证明不能替代撤销证明。CPU、内存、磁盘、网络路径延迟等完整 Agent 遥测尚未实现，不能用固定 0 或示例延迟充当实测。
- 免费工具在客户自有 VPS 执行部署 MSBOOST、配置中转服务器或自备前置机时，写入专用 `/etc/sysctl.d/zz-msboost-bbr.conf`，依次执行针对该文件的 `sysctl -p`、全局 `sysctl --system`、再次对该文件 `sysctl -p`，再逐项核对全部 13 个 BBR/FQ 与 TCP 参数。重复执行保持幂等，不覆盖整份 `/etc/sysctl.conf`；仅在旧项目文件内容完全匹配且归 root 所有时清理。控制执行机和本站捐赠权益节点明确不应用该步骤；内核不支持、文件安全检查失败、加载失败或任一实际值不匹配时任务必须失败，而不是假报已配置。
- **尚未交付**UDP运行链、TCP/TLS之外的隧道协议、FLVX `2.2.0-alpha4`全量迁移或协议兼容保证、已有TCP会话无损故障切换、自动端口冲突重排、节点网卡/地址自动发现以及可配置租约时长。入口可配置多个地址但单一客户端JSON只固定使用其中一个，不表示已实现多入口自动故障切换。

## 备份与恢复

- 当前实现加密整站业务状态、本地私有文件、计划调度和SFTP目标传输，远端写临时文件并读回校验后重命名。当前备份是平台数据，不是客户VPS整盘；浏览器免费本地文件不在其中。外部主密钥需要另外保存。
- 网页安全恢复要求备份 SHA256 与当前恢复范围摘要的预检、明确 RESTORE、维护模式、无运行任务；纯 v1 核对租约，v2/混合状态不能由旧租约推定停止。先写受保护的私有回滚备份，再恢复；会话退出、Agent令牌撤销、自动备份计划暂停、路线停用。
- 安全恢复采用白名单：仅站点设置、文章附件、线路、节点与执行机定义可从快照恢复。当前完整用户身份、枫叶权益、兑换记录/兑换码/去重记录、渠道配置、工单、任务、审计、用户规则与计量集合整体保留，包括尚未知晓的新集合；不把财务行零散合并。现有用户规则引用的线路及节点保留当前拓扑，预检披露。兑换/渠道开关保留当前值，维护强制开启。
- 完整灾难恢复使用独立 msboost-restore 离线工具：原密钥解密和关联校验后，仅创建全新 PostgreSQL 数据库或全新 SQLite 目录，读回核验；不读取、覆写或删除损坏的原业务库。不含备份之后的新交易，导入后保持维护、关闭支付、撤销凭据，停止原服务后手工切换及对账。它不能代替运营确认快照新旧、恢复目标或退款/补单，见 [恢复指南](backup-recovery.md)。
- 未过期捐赠权益配置密文保留，恢复后仍可登录下载。涉及 v2 的恢复保留运行 segments、端口、旧目标、命令及撤销关联，进入 recovery_required；完整灾难恢复对含旧 v1 segments 的快照也保守保留，因为旧库不能证明节点后来没有升级。令牌失效不等于业务停止。支持恢复协议的节点可通过 [本机受信恢复](relay-recovery.md) 逐规则接管，其他情况需独立确认停止；财务和营业开关仍需人工核对。历史运行任务不自动重放。
- 本机删除前核验有效副本数，恢复前回滚副本受保护。整站 SFTP 远端保留清理仅在管理员明确启用并且新包上传、回读和候选逐份校验成功后执行；网页备份与整站备份不是同一保留流程。**尚未交付**S3/对象存储后端、失败上传重试队列、按数据库/附件/审计等选择备份范围、异机主密钥迁移向导以及生产灾难恢复/支付对账演练。备份失败状态可见，不表示已有可恢复远端副本。

## 数据层与验收边界

- 支持SQLite与PostgreSQL连接。当前业务状态存于单行JSON文档，SQLite使用BEGIN IMMEDIATE、PostgreSQL使用FOR UPDATE配合事务串行化读改写，已覆盖低并发正确性测试。不是独立关系表、行级财务账本分区或大规模查询索引架构。
- **尚未完成**按用户/任务/订单/流水/流量分表迁移、1000用户容量和持续负载测试、多实例高可用、长时间流量/数据库增长压测、PostgreSQL独立部署并发压测，以及完整权限渗透与浏览器XSS专项审计。不能宣称已具备1000用户生产容量。
- 自动化覆盖范围必须以对应版本的实际测试结果为准；测试文件存在不等于已经运行通过。商务边界、并发兑换码、支付通知、目标认证、入口隐私、IPv6、监听 ACK、流量计量、恢复防回滚，以及密码、续兑/体验限制、排序、随机端口、流量重置、诊断、等级、清理、工单和 BBR 等功能，都须以目标版本的 CI 和现场验收记录核对。
- 既有真实 Linux 验证使用授权的临时 VPS；测试环境、控制面版本和 Agent 版本须在记录中逐项注明。真实渠道扣款、实际游戏连接、容量与异常网络条件不能由源码或测试脚本存在推断通过。
