## 真实 VPS 与隔离反例

| 范围 | 已核验结果 |
|---|---|
| 控制面升级 | 原 v0.3.2 控制面升级至 v0.3.3；原有 1 个管理员账号及 3 台 Relay 保留，3 台 Relay 升级后保持在线。另有 1 台新版 Executor 在线。网站升级不会自动升级独立 Agent。 |
| 控制面修复 | 在正式 v0.3.3 控制面执行 `msboost repair` 成功；修复前后版本、管理员凭据、主密钥和数据库密码保持不变，业务记录数量不变。修复完成后，原有 3 台 Relay 与 1 台 Executor 均恢复在线。这验证的是保留数据的修复，不是整站卸载或恢复。 |
| 免费全新部署 | 在三台分别运行 Debian 11、12、13 的客户 VPS 上完成本版全新部署；每台均核对新生成配置、BBR/FQ 参数和公网 TCP 可达。该“部署 MSBOOST”流程不是 DD 重装。 |
| 免费自备中转及定域清理 | Debian 11 客户 VPS 的自备中转配置完成安装，并通过公网 TCP 连通检查。随后执行 `cleanup-preview`，预览列出 2 项受管资源；按摘要确认清理后，自备中转 systemd 单元已移除，原 MSBOOST 直连服务仍为 active，原直连配置文件保留。此项是自备中转的受管资源清理，不等于整站彻底卸载。 |
| 不支持系统的前置拒绝 | 在隔离、只读、断网且无宿主机目录挂载的 Docker 容器中，用实际执行机 Debian 前置检查脚本分别验证 Ubuntu 22.04（非 Debian ID）与 Debian 10（版本过旧）被拒绝；检查停在 `unsupported_debian/preflight`，未进入 apt、sysctl 或文件写入阶段。这是容器反例验收，不声称已在真实 Ubuntu/Debian 10 VPS 上执行完整任务。 |

## 未覆盖范围与使用边界

本轮**未**实测真实游戏协议登录与体验、真实商户支付、外部邮件实际投递、arm64 真机运行、v0.3.3 面板 DD 重装、完整整站卸载/恢复，以及高并发/大流量容量上限。此前版本或用户另行完成的测试不替代上述项目的本版验收；公网 TCP 可达也不等于游戏协议通过。上文 Debian 11 自备中转的定域清理已经实测，不应与尚未重跑的整站卸载混淆。

控制面正式支持 Debian 12/13；客户 VPS 免费部署和自备中转的兼容范围为 Debian 11/12/13。Debian 11 属于兼容目标，不建议作为新的公开生产承载系统。现有控制面及 Agent 不会因 Release 发布自动升级；有状态节点应先备份并在维护窗口核对升级影响。
