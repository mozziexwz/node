# MSBOOST v0.1.2 安装器修复

v0.1.2 修复真实 Debian 12 安装时 `/etc/os-release` 的 `VERSION="12 (bookworm)"` 覆盖项目版本号的问题。v0.1.1 会因此生成非法镜像名和下载地址，请使用 v0.1.2。新增真实 Debian 12 平台/CLI 回归测试，以及保留原始配置和密钥的失败首次安装恢复路径。配置替换采用同目录原子重命名。

如果 v0.1.1 安装失败且报 `node:12 (bookworm)`，不要彻底清理或重新生成密钥。重新下载 v0.1.2 的根安装脚本后执行：

```sh
bash /root/msboost-install.sh upgrade --version v0.1.2 --recover-incomplete
```

该参数只接受明确的旧版错误记录，且必须没有 MSBOOST 容器、四个站点数据卷、专用网络和原应用 imageID；检查失败就停止，不接管已有业务。成功拉取镜像后先备份原配置和部署脚本，再保留原域名、管理员密码、数据库密码和主密钥完成安装。具体下载命令见部署文档。普通运行中的安装仍使用正常升级和数据库备份流程。

v0.1.1 曾修复动态 IP 与 Caddy 固定地址冲突、GitHub 单行 JSON 的升级版本解析；v0.1.0 没有生成正式 Release。旧标签不覆盖。

面向 Debian 12（amd64 / arm64）。网站默认使用 Docker Compose 拉取 GHCR 预构建镜像；发布包与独立执行机/节点二进制提供 SHA-256 校验。

- 一键安装、升级、修复、状态和日志；卸载默认保留数据库与密钥；彻底清理是独立双重确认操作。
- 按补充说明完善用户单位与排序、卡密记录、套餐限购、邮箱购买门槛、节点与隧道、文章和工单。
- 后台提供执行机与节点注册令牌及一键安装入口。

先在测试 VPS 验收。重装系统、客户 SSH 执行和网络配置具有实际破坏性，不会由本站安装脚本自动执行。完整在线任务需要 HTTPS 域名及已注册执行机；IP HTTP 模式仅用于界面调试，不能代替生产 HTTPS。

优先拉取 GHCR 镜像；若镜像包尚未公开或仓库访问失败，自动改为下载同版本 Release 中经过 SHA-256 校验的预构建镜像归档并导入 Docker。两种来源均失败则停止，不会静默切换本机构建。参考仓库 README 和 docs/deployment.md。
