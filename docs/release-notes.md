## v2.5.0 · 中转码、SSH 密钥登录与节点引擎升级

### 节点引擎升级与低熵流量模式

- 节点引擎 mihomo 从 v1.19.30 升级到 v1.19.32，内置 mieru 从 v3.35.0 升到 v3.38.0。包含 mieru 监听遵守 `listen` 设置、YAML 解析库更换、域名规则匹配修复，以及 mieru 服务端的内存和 CPU 优化。节点写的是 `listen: 0.0.0.0`，实测升级前后都是同时接受 IPv4 和 IPv6 的双栈监听，没有变化。
- 安装脚本写死 v1.19.32 各架构文件的 SHA-256，下载后先与写死值核对，再与 GitHub 发布摘要核对；用 `MSBOOST_ENGINE_VERSION` 指定其他版本时只核对 GitHub 摘要，并打印提示。
- 新增低熵开关 `MSBOOST_LOW_ENTROPY`，只接受 `off`、`56`、`48`、`40`、`32`，其他值在改动服务器之前直接报错退出。**生成新凭据的部署（面板「部署 MSBOOST」、首次安装、`MSBOOST_FORCE_FRESH=1`）默认 48 档**；沿用凭据重新运行时保持安装状态里记录的档位，旧安装没有记录时为 `off`，与之前完全一致；显式传入的值优先。
- 低熵只设置流量模式里的 `lowEntropy.mode`，其余项仍由 mieru 自动生成。档位同时写入节点监听（`traffic-pattern`）、客户端配置 `/root/直连.json`（profile 里的 `trafficPattern`）、部署自测的出站和安装状态（`LOW_ENTROPY=48`）；自测因此真正走一遍低熵路径。48 档的正文流量约为原来的 1.34 倍，不增加延迟；不开 TCP 分片。
- 部署结果、配置下载和任务记录处提示：新配置需要 MSBOOST 启动器（node_launcher，内置 mieru v3.38.1）；旧版 BAT 启动器请把 `msboost.exe` 更新到 v3.35.0 以上。「配置中转服务器」生成的中转配置原样保留 `trafficPattern`。

存量节点不需要处理，继续使用 v1.19.30。需要升级某台节点时，在节点上以 root 不带参数运行新版 `installers/node/msboost.sh`：脚本沿用原用户名、密码和端口，低熵保持原来的设置（旧节点为 `off`），校验或自测失败会自动回滚，服务会重启几秒；多 IP 或 NAT 的机器加 `MSBOOST_SERVER_IP=原入口IP`。不要用面板「部署 MSBOOST」升级已有节点，它会生成新的凭据。旧 BAT 用户加载新部署的配置失败时，可以删掉配置里的 `trafficPattern` 一项，或在节点上用 `MSBOOST_LOW_ENTROPY=off` 重新运行脚本生成新配置；节点两种客户端都接受。

### 中转码与 SSH 密钥登录

- 「配置中转服务器」分为三种方式：使用中转码（默认）、生成中转码、手动配置中转（原有功能）。拥有者生成中转码发给朋友，朋友上传自己的 MSBOOST 配置文件即可在拥有者的中转服务器上建立中转，**拥有者不用交出 SSH**；可以搭配使用者自己的前置机。用中转码建立的中转与手动配置的一样长期运行。
- 中转码的规则：可使用 1–10 次（默认 1），有效期 1–72 小时（默认 24，快捷 12 / 24 / 48 / 72 小时），带宽 1–10 Mbps（默认 5），每人同时有效 5 个；中转（以及前置机）全部建立成功才计次，多人同时使用先预占次数，失败归还，前置机失败时删除刚在拥有者服务器上建立的中转。生成时先用 SSH 做一次只读检查（Debian 11–13、中转运行条件），检查通过才生成并固定服务器指纹。生成检查和使用中转码都计入原有的「每 15 分钟 5 次」操作限额；使用尝试另按每账号每小时 10 次、每 IP 每小时 30 次限流。
- 网站只在中转码的次数和有效期内用主密钥加密暂存 SSH，到期、用完、作废、拥有者账号停用、管理员停用或紧急删除时立即删除（每分钟检查），每次删除写审计。整站备份、安全恢复和灾备归档都不包含暂存的 SSH，从备份恢复后所有中转码一律失效。
- 新菜单「中转码管理」：我的中转码（显示、复制、复制分享链接、详情和使用记录、调整有效期和次数、作废时可选同时删除它建立的中转）、中转服务器管理（用暂存的 SSH 或临时输入的 SSH 读取服务器上全部 MSBOOST 中转，按使用者修改带宽、暂停、恢复、重新启动、删除，可批量；单独限额每 15 分钟 20 次）、我使用的中转。中转服务器上的每条中转新增使用者记录 `meta.json`（使用者完整 QQ 邮箱和节点 IP，不含节点认证），升级前建立的中转显示为「升级前配置」。
- 手动配置中转新增「中转带宽」选择（1–10 Mbps，默认 5），并写入使用者记录。
- 全站填写 SSH 的地方（部署 MSBOOST、手动配置中转、前置机、生成中转码、中转服务器管理、DD 系统、核查 / 清理）都支持「密码 / 密钥」两种登录方式，默认密码。密钥为 OpenSSH 格式的 ed25519、ECDSA、RSA 私钥，可带口令，不超过 16 KB；私钥只用于本次任务，不进入任务记录，也不保存到浏览器。DD 用密钥登录时可选「继续使用当前密钥」（把公钥写入新系统，不设 root 密码）或「改用密码登录」。
- 管理员：系统设置新增「中转码」标签页（功能开关、是否允许用暂存的 SSH 管理中转服务器、使用时邮件提醒拥有者、各项上限和限流、暂存状态、立即删除全部暂存的 SSH）；平台管理新增「中转码审计」（按用户查看、作废全部、停用 / 恢复功能，SSH 删除记录）。
- 操作限额提示条前加「操作限额」。手机宽度下工具页的配置文件选择框不再撑出横向滚动。

**执行机需要升级。** 中转码、中转带宽、使用者记录和密钥登录只派给新版执行机（新增 `X-MSBOOST-SSH-Key`、`X-MSBOOST-Relay-Code` 能力声明）；只有旧执行机在线时，手动配置中转也会提示升级，部署 MSBOOST 和 DD 的密码登录照常可用。已有中转、节点和捐赠权益线路无需改动。

验证使用本地隔离环境、GitHub CI 和 6 台 Debian 12 / 13 实机 VPS：面板全新部署（密码和密钥登录，默认 48 档）；一台 v2.4.1 节点和一台现有 v1.19.30 节点原地升级，凭据、端口和客户端配置不变，强制自测失败时自动回滚到 v1.19.30；node_launcher 内置的 mieru v3.38.1 连接 48 档和未开启的节点、带和不带低熵的配置都正常，连续使用 2 小时没有断流；官方 mieru v3.34.1 加载 48 档配置失败，v3.35.0 正常。中转码的生成检查、使用（含前置机）、失败归还次数，用完、到期、作废、停用和删除全部时删除暂存的 SSH，服务器重装后拒绝使用，以及中转服务器管理、限速、手动中转、卸载预览与清理、DD 后用原私钥登录，均在实机上通过。

- 增加协议、安装事务、清理及实际 BAT 兼容测试，以及 Python 3.9/3.11/3.13 的 CI 矩阵。

两台 Debian 12 测试 VPS 已通过原部署入口、三种握手模式、真实透明转发链路、服务联动及失败回滚验收，并完成一台节点的真实清理重装。备用游戏目标连接超时仍记录为失败；完整证据和适用边界见[全程 TCP 测速说明](msboost-tcp-probe.md)。

网站与执行机需分别升级。已有 MSBOOST 游戏节点不会自动获得 v2 测速能力；本版支持原全新部署流程，重新部署会替换节点凭据和入口端口，应安排维护并载入新客户端配置。透明转发节点只需保持原有完整通道，测速服务位于最终执行目标连接的 MSBOOST 节点。

## v2.1.0 · 节点与中转管理改进

- 修复空站恢复后首次注册被错误冻结、零下发记录的失败注册无法取消的问题；有业务或记录不完整的节点仍须核查，删除不等于远端停服。
- 安装前核对面板与令牌，安装后必须取得本次进程的真实同步结果。注册响应丢失可限时重试；旧缓存、进程 active 和文件回滚不再等同上线成功。

- 修复自备前置机就绪判断，改为后台任务；失败时标明是否需要核查客户 VPS，提供本次任务的定向清理。
- BBR 优化单独报告结果，失败尝试回退本次内核参数，不重载其他软件的网络配置。
- 加强重复主机、重叠地址端口池和待停止资源校验。历史租约到期不作为释放未知转发的依据，当前运行只使用 keep_last。

## v2.0.1 · 系统 Caddy 全新部署版
