# 发布说明

## v1.0.1 · 出口节点诊断与权益等级

- 修正中转诊断的测量位置：旧版约 60 ms 的“入口连接延迟”是面板到入口节点的 TCP 建连耗时，不能代表节点到客户 MSBOOST。新版由线路最后一个受管出口节点，对该用户当前运行规则中已验证的目标 IP:端口发起一次 TCP 建连，并回报出口到客户目标的耗时。失败或超时不显示虚假的 0 ms；旧版、离线或未确认运行规则的出口 Agent 不会退回面板测量。
- 诊断结果明确标记“出口节点→客户 MSBOOST TCP 连接延迟”，不包含入口、中间节点，也不是游戏实际延迟。仅固定规则目标可被探测，无通用扫描或任意命令入口；诊断有身份、期限、并发和请求频率限制。
- 管理员的用户列表显示 L1–L3 权益等级，编辑用户可修改等级；会员的有效捐赠权益角标显示当前等级。修改等级不重算权益到期时间。

先备份并在维护窗口将面板升级到 `v1.0.1`，再分别在受管出口 VPS 下载该版本 `agent.sh`，使用 `--upgrade-in-place --acknowledge-relay-restart` 原地升级 Relay Agent；完整命令及令牌处理见[Agent 安装说明](agent-installation.md)。面板升级不会自动更新独立 Agent；Agent 重启会中断现有连接。所有出口节点完成升级并重新显示在线后，再验证诊断。正式镜像及 Release 资产以 GitHub Actions 成功发布为准。

## v1.0.0 · 正式版

本版整合现有自备 VPS 部署、捐赠权益转发、网站 DD、执行机与节点管理、兑换、工单及备份功能，并按最终用户协议与补充说明 3.3 整理界面。安装器的公开菜单收敛为 1–12 项；受保护恢复能力继续保留在内部维护模块，不能绕过业务停止与备份门禁。

- 免费部署、配置中转及 DD 的提示与按钮文案更新；SSH 主机身份变化时把完整处理说明另起一行。
- 后台删除节点后提供可复制的独立 Agent 清理命令；未关联业务的节点可按明确断流确认进行全新重注册，旧管理身份失效。
- 免费自备中转和捐赠权益节点转发默认拒绝可识别的明文 SOCKS4/5 握手，不提供放行开关；MSBOOST 客户端本机的游戏 SOCKS5 入口不受此限制。加密或刻意伪装的代理流量无法仅靠入口特征检测保证拦截，详见[安全边界](security-and-limits.md)。
- 网站升级不会自动替换已安装在其他 VPS 上的旧 Agent 或已有中转实例。新版控制面对旧执行机、旧节点拒绝分配新的转发配置；旧转发仍保持原运行状态，必须在维护窗口分别升级受管程序、重配免费中转并核对防护。Relay 原地升级会重启服务并断开现有连接，不应描述为无感升级。
- 网站《用户协议》使用本版正文；站点升级需要运行包含本版网页的镜像，单独更新安装脚本不会替换已运行网站。

控制面支持 Debian 12/13；客户 VPS 免费工具支持 Debian 11/12/13；网站 DD 固定重装 Debian 12。默认 Relay 离线策略为 `keep_last`，控制面失联时保留最后下发的业务规则，但撤销、过期、流量封禁等新决定会延后执行；节点重启或重注册仍可能断开现有连接。完整边界见[安全模型与限制](security-and-limits.md)与[Relay 协议](relay-v2-contract.md)。

安装入口固定到 v1.0.0；运行前请确认[Release](https://github.com/mozziexwz/node/releases/tag/v1.0.0) 已包含 `SHA256SUMS`、部署包与对应架构的预构建镜像，并核对摘要：

```sh
curl -fsSL --proto '=https' --tlsv1.2 https://raw.githubusercontent.com/mozziexwz/node/v1.0.0/install.sh -o /root/msboost-install.sh
bash /root/msboost-install.sh
```

正式标签、双架构镜像和 Release 资产的发布状态以 GitHub Actions 实际结果为准，不能仅依据源码版本号判断。升级现有站点先做离机备份，并在维护窗口单独更新 Agent；不自动迁移或重启独立节点。游戏登录、真实支付、邮件投递、arm64 真机与容量上限需要运营者在目标环境逐项验收，不能从本地单测推定已通过。
