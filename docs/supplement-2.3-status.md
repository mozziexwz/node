## 已实现：控制面离线保留与受保护维护

已新增本地试验 v2 / `keep_last` 核心实现：显式命令与停止确认、配置与墓碑持久化、无租约离线保留、相同运行配置不重启、历史周期与显式流量 ACK，以及恢复资源冻结。默认仍是 v1 短租约；安装器没有自动开启试验模式。不能把源码实现或本机 TCP helper 测试当成真实 GOST / 生产不断流验收。

本机运行时测试覆盖独立子进程与不自动重连的 TCP 连接、管理认证失败继续运行、无效候选保留旧配置、明确停止后确认、缓存恢复及账务补报。Linux 排他锁、root socket 和真实 GOST 受信恢复已执行，具体证据见末节；交叉编译本身不替代运行测试。

停站备份安全门禁：逐段能力/命令确认检查与冻结写入共用数据库事务，覆盖并发规则变更、任务领取和后台写入；网页备份增加持久进行中标记。脚本获准后才停止原控制面容器，全部导出完毕并确认解锁后才恢复；失败保留原私有凭据。默认 v1 / 混合或未确认链路阻止停站备份，没有静默强制绕过。新增菜单 14 的 root 手动维护路径，明确接受旧链路中断后仅放宽离线能力检查，其余门禁保持；定时备份不能使用该路径。

已补上异常网页备份的受保护人工核销：菜单 13 / `msboost backup-reconcile`，仅原服务器 root 交互式操作。新网页备份持有原数据卷文件锁，并将锁的随机身份、设备号和 inode 与活动记录绑定；核销重新独占原锁、在同一数据库事务中核对精确记录后，才将该活动转为 `interrupted_unknown` 审计。不会标记备份成功、删除备份文件、解除整站停站门禁或中转恢复冻结。旧无锁记录、原锁丢失/损坏、替代数据卷和证据不一致仍拒绝；没有超时自动核销。详见[操作边界](disaster-backup.md#异常网页备份核销本地实现尚未发布)。

核销与锁模块已通过本地 Go 回归（包括上传 panic、锁变化、并发持锁、事务失败和幂等重试）、管理脚本模拟及实际 Go 环境模板校验。Windows 文件锁测试采用进程内模拟；临时 Debian 12 的真实跨进程原 inode 锁、进程死亡后释放、只读/替代 nonce、换 inode 和权限变化拒绝已通过。Docker 原卷与 PostgreSQL 的执行记录见末节，不由 Windows 模拟推断。

本轮继续完成以下原未整改项，操作说明见 [受信恢复与 TLS 维护](relay-recovery.md)：

- 节点 root Unix socket 快照、持久恢复冻结和私有计划热接管；完整状态/凭据原子更新，拒绝旧并发控制响应。
- 控制面菜单 15：差异核对、逐规则 adopt / stop / hold、精确 ACK 后显式 finalize。拒绝缺项、孤立/坏记录、过期确认、身份重置、拓扑变化和历史撤销后复活；维护、支付与财务不自动更改。
- 证书 root 显式维护，仅影响选中规则，心跳/统计不使配置审核指纹失效，不关闭 TLS 验证。
- 安装器显式开启 keep_last、活动 Agent 重启确认、两种角色共用二进制的全局安装锁、写入前二次准入及兼容回滚保护；已有 v2 状态禁止静默降为 lease。
- 严格单调命令历史、停止墓碑幂等复用，修复重复受信停止完成后误阻塞备份的问题。
- 已停止节点删除时保留不可重新注册的终态退役证明，解决历史记录使未来恢复永久阻塞的问题；记录丢失、旧身份插回或旧定义复活均拒绝。计量降级只提供 root 审核后的“全部明确撤销→终态复核→退役”退出路径，不清除降级、历史用量或待核对记录，不恢复运行授权。
- 配置/墓碑和计量容量有界；不自动清理终态历史换空间。维护时先明确停止旧实例，再退役身份/重新部署，不承诺无限历史或升级保连接。

真实环境验收进行中，结果以最后一节逐项记录为准，不由源码/交叉编译/CI 配置推断通过。实现范围和中断边界见 [Relay v2 契约](relay-v2-contract.md)。

`keep_last` 期间无法实时执行控制面新发生的封禁、到期或耗尽指令，需在最终协议和运营说明中明确恢复连接后的处理；不承诺节点自身重启后保留原有 TCP 连接。
