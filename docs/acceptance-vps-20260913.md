# 补充说明 2.1：真实 VPS 排查与验收

日期：2026-09-13。使用用户明确授权可重装、清理的三台 Debian 12 amd64 临时 VPS。主站控制面不在破坏性测试范围；凭据不进入仓库或本报告。

## 已确认原因

| 问题 | 真实证据 | 修复 |
|---|---|---|
| 自备中转 `integrity_failed` | 三台 `/run` 均为 `noexec`，旧执行器在其中执行 GOST；旧代码再次复现同一失败 | 在受保护磁盘目录暂存、校验并原子发布 GOST；不关闭 SHA256 或改变挂载选项 |
| 中转越过校验后仍退出 | 实际 systemd 日志为 `Unsupported Config Type ""`；凭据路径 `%d/config` 没有扩展名 | `LoadCredential=config.json` 与 `%d/config.json` 配对；仍使用 DynamicUser 和凭据隔离；耗尽启动重试返回明确诊断 |
| DD 在准备阶段失败 | 固定上游默认询问用户名；旧调用缺失该参数，无交互回归复现失败 | 显式 `--username root`，并用 `</dev/null` 防止读取外层脚本；脚本仍来自固定 `bin456789/reinstall` 提交 |
| 执行机显示 Cloudflare IP | 线上心跳元数据显示边缘地址，代理原配置只转交最后一跳 | Caddy 仅信任官方 Cloudflare 网段，严格解析后向应用转交单个已验证 IP；直连伪造头无效 |
| 文件更新但代理未加载 | Compose 服务配置不变时，不因绑定的 Caddyfile 内容变化重建；旧进程仍使用旧配置 | v0.2.2 先等待数据库/应用健康，再仅强制重建 Caddy；失败回退也加载旧代理配置，不强制重建数据库 |

Cloudflare 来源显示不参与执行器向用户填写的目标 IP 建立 SSH 连接；上述中转错误发生在目标 VPS 的下载后执行与 systemd 启动阶段，不应归因为“开了小云朵”。

上述三个商务/恢复阶段只证明公开 **v0.2.0** 镜像在独立合成数据环境中的相应路径，不是主站数据恢复，也不是本次新修复版本的全量生产验收。该栈未配置 SMTP、商户渠道、远端备份目标或真实付费 Agent；空的流量/规则集合保留校验不能替代实际多跳计量验收。收尾已停止 QA 应用、数据库和临时代理，新旧数据库、原始主密钥及私有备份保留，VPS3 原节点继续 active。

免费远端脚本功能由项目真实执行引擎直接调用三台临时 VPS 验证，不是在旧版主站任务队列上把历史失败改为成功。租约用例使用独立合成控制服务和六秒短租约，未注册到主站、未修改生产租约默认值；首次用例在全部连接断言后因测试服务夹具清理阻塞而超时，修正测试收尾后完整重跑通过，生产运行代码未因该用例改动。

验收驱动曾发生两类辅助问题，均不计为产品故障：内部网络下声明的宿主端口未提供可用回环入口，改由仅监听宿主回环、逐连接核验 QA 容器身份的临时代理连接，未放开内部网络；安全恢复驱动误拒绝包含数字的 sha256 字段，恢复请求尚未发送。后者经只读核对阶段、余额及用户数后，仅续执行恢复尾段，没有重复充值或创建用户；原快照经本机现成加密库在内存解密和完整性校验后生成脱敏哈希，作为离线新库的独立比较基准。Docker 对内部网络的宿主直连能力有明确说明。[Docker 官方文档](https://docs.docker.com/reference/cli/docker/network/create/#network-internal-mode)

- 指纹提示面向普通用户，审计名称为“验证指纹”。
- 卸载卡片与部署表单同列等宽；“继续”只进行后台预检，成功后提供“确认删除”。不再显示内部路径清单或要求手输确认词。
- 后端预览摘要、有效期、主机与用户绑定、一次性消费、所有权和范围限制不变。新旧 GOST 凭据文件名必须完整配对，混配或未知名称拒绝清理。
- TypeScript、前端构建、隔离浏览器卸载状态流、Go 单元测试和 vet 通过。
- 真实 GOST 回归重现旧无后缀错误，并证明新 `.json` 配置可启动转发。
- 真实 Caddy 回环转发验证直连伪造头拒绝、可信边缘解析、IPv6、XFF 右侧解析及只向应用发送一个 IP；不是冒用 Cloudflare 公网地址。
