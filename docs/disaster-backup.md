# 在线整站备份与恢复

在面板 VPS 以 root 运行 `msboost`。后台“备份与恢复 → 整站备份状态”显示同一份记录。

| 菜单 | 用途 |
| --- | --- |
| 8 立即整站备份 | 不停网站或节点，导出一致性快照；配置了异地目标时上传并完整回读校验 |
| 9 配置并验证自动备份 | 验证 SSH 身份、密码及目录读写后才保存并启用；随后立即执行首份完整备份 |
| 13 备份状态与记录 | 每次本地、异地、清理结果及实际 systemd 计划 |
| 14 测试异地连接 | 验证登录、SFTP、测试文件写入、回读、删除 |
| 15 重传已有备份 | 输入本地文件路径，避免重新导出，相同文件可安全重试 |
| 16 恢复节点管理连接 | 灾难恢复后的交互向导，不用于日常升级 |

错误密码、指纹不符或目录不可用时，保留原配置和计划。指纹须从可信控制台核对。“计划已启用”“连接测试通过”“已有成功备份”分别显示，不能相互代替。首次完整备份失败会明确记录，计划仍保留以便下次重试。每天时间按 VPS 本地时区执行，可能延迟 60 秒；绕过脚本修改 systemd 时以菜单 13 实际计划为准。

异地失败不删除已校验本地包；先修正配置、菜单 14 测试，再用菜单 15 重传。旧包清理失败与新备份失败分别显示。可在后台启用管理员异常邮件，默认关闭，依赖已配置 SMTP；邮件仅辅助提醒。

## 备份范围与保密

业务状态在 PostgreSQL 只读事务中一次性读取，包含用户、订单、枫叶、权益、流量、节点线路、任务、文章附件，另保存原站点密钥、环境配置和部署文件。不复制历史备份、缓存、客户 VPS 磁盘、浏览器文件或进程状态。HTTPS 证书恢复后重新签发，需域名、DNS、80/443 与签发服务可用。

历史任务和暂时离线节点不阻止在线备份。不清空任务，不重启 Agent/GOST；恢复时历史任务不自动重放。快照之后的新交易不在包内，恢复后须核对账务。

压缩包包含原密钥和密码，仅 root 可读；外层并非密码加密保险箱，只存放可信服务器，绝不公开上传。校验发现损坏，但不能证明被攻击服务器提供的文件可信。

## 全新目标恢复

停用或隔离原面板，准备全新 Debian 12/13 VPS，复制备份到 root 私有目录，下载与备份来源版本一致的正式安装脚本并选择菜单 10。工具完整校验后创建全新数据库，不覆盖已有站点，不执行包内脚本。先按原版本恢复成功，再使用正常升级流程；不可把旧快照直接跨版本导入。

恢复后保持维护、关闭支付与兑换，旧会话和管理凭据失效。核对快照之后的收款、权益、流量，再运行菜单 16 恢复捐赠中转节点连接。执行机需重新关联，不重放部署/DD。验收后开放营业，用菜单 9 重新设置备份。

仍支持读取旧备份包，避免已有备份失效；这不是继续支持旧中转租约模式。

## 失败处理

查看菜单 13 或 `journalctl -u msboost-disaster-backup.service -n 60 --no-pager`。新备份不创建停站冻结。旧工具异常退出遗留的冻结须使用那次原始解锁材料处理，不可删门禁绕过。旧日志的 `gateActive:false/released:true` 仅说明门禁解除，不代表产生备份。

失败保留 root 私有工作目录。不要为备份失败清空业务或重装节点。当前支持官方单机 Compose 站点；自定义外部文件、超出快照上限的数据需另行备份。应定期在隔离全新目标验证恢复。
