# 管理员本机修改密码

普通会员使用登录页的邮箱找回密码；管理员不提供邮件找回入口。管理员忘记密码时，在**控制面 Debian 12 VPS** 上以 root 运行：

```sh
msboost admin-password
```

也可运行 `bash /opt/msboost/install.sh`，选择 **12）修改已有管理员密码**。部署文档把固定版本的 `install.sh` 下载后命名为 `msboost-install.sh`，它是同一入口，也支持 `bash msboost-install.sh admin-password`；并非另一个独立发布资产。已经安装的管理脚本及应用镜像必须包含此功能；只下载新版入口而保留旧镜像不会给旧程序增加命令，请先正常升级。

1. 在本机终端输入目标**已有管理员**邮箱，输入不回显。
2. 输入新密码两遍，每次均不回显；长度为 **12–72 字节**（汉字等 UTF-8 字符占多个字节）。
3. 确认显示的目标邮箱，并输入 `RESET 管理员邮箱`。其他输入、Ctrl-C、EOF 或两次密码不一致都会取消，输入完成之前不会调用改密工具。

不接受邮箱/密码命令行参数，不读取环境变量中的新密码，不允许用文件或管道代替终端提示。新密码只在内存中处理，经 stdin 管道传给已安装、校验身份的官方工具镜像；不写入 `.env`、临时密码文件、进程参数、容器日志或审计。数据库只持久化 bcrypt 密码散列。

成功后仅修改目标管理员密码、撤销该管理员已有登录会话和未完成的密码恢复请求，并记录不含密码的本机审计。不会创建账号、提升普通会员权限、修改角色、账号状态、维护开关、余额、套餐或转发配置。若账号本身被停用，改密不会自动重新启用账号。

## 服务与数据安全

本命令**不停止或重启** server、Caddy、数据库、Relay Agent 或 GOST。它复用已安装镜像的固定 image ID，加入本机现有数据库容器的网络命名空间，连接其 loopback 地址，不拉取新的镜像、不调用安装初始化、不建空数据库或表。

控制面 `Store` 每次事务都会重新读取 `control_state`；PostgreSQL 用 `SELECT ... FOR UPDATE` 串行化写入。改密工具复用相同事务边界，读最新状态后修改目标账号，避免覆盖同时到达的支付、流量和用户操作。该命令本身不引入旧版 45 秒中转租约的停站风险，但不改变其他操作的既有租约行为。

`.env` 的 `ADMIN_PASSWORD` 是首次初始化值：系统检测到已有管理员后不会用它覆盖现有账号。**不需要把新密码写入 `.env`**，升级、修复和正常重启也不会把管理员密码回退为该初始化值。

数据库不健康、镜像身份不匹配、邮箱不存在或属于会员时拒绝修改，不自动修复或重建站点。若终端或 Docker 在提交后意外断开，显示“未确认成功”不一定表示数据库未提交；可先尝试新密码登录，或重新执行本机改密。原服务一直保持原状态，无需额外恢复服务。
