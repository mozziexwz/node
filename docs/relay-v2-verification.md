# Relay v2 验收证据分层

更新：2026-09-22。整改已随 [v0.2.4](https://github.com/mozziexwz/node/releases/tag/v0.2.4) 发布；30 分钟为本轮耐久验收标准，已通过。真实 GOST、真实控制面、真实数据库、模拟协议和静态审查仍是不同层次；测试文件存在或交叉编译通过不等于已执行成功。

## 本轮执行入口

- 本机：`go test ./... -count=1`、`go vet ./...`、TypeScript/Vite、HTTP 9 项、浏览器 35 项已通过。Windows 会跳过 Linux 专用测试。
- 临时 Debian 12 VPS：`deploy/relay_endurance_test.sh` 使用新网络命名空间和固定校验的 GOST 3.3.0，三拓扑分别运行生产 `relayruntime.Run`。每条原 TCP 只拨号一次，不允许重连。控制端为受控协议服务器，不是实际 MSBOOST 后端。
- `TestRealControlBackupPauseAndOfflineConnection` 使用真实控制后端、SQLite 事务、注册/命令/流量 ACK、严格备份门禁及生产 Run/GOST。实际关闭 HTTP 监听的5分钟和30分钟两轮均已通过；长轮实测30分0.52秒，重新监听后26.339秒取得新鲜ACK。它不打包整站归档，不代替完整灾备脚本验收。
- `deploy/linux_validation_test.sh` 为显式临时测试脚本，不是客户安装器：使用随机 Compose 项目/数据卷、容器私有网络回环探针，不发布宿主端口，检查网段冲突，仅清理本轮所有权标签资源。实际 Linux 原锁、root socket、原卷只读权限以及真实 PostgreSQL 批次已通过；各独立测试结果和跳过项单独写入[整改状态](supplement-2.3-status.md)。

首次真实耐久试跑曾因测试 Unix socket 路径超过 Linux 长度限制失败；仅缩短了测试私有路径，重新编译后再执行，不将失败轮计作通过。控制面部署、现有转发、真实客户邮箱和商户款项不在本轮外部写入范围内。

## 发布边界

这些证据已满足本轮 30 分钟耐久标准，但不足以宣称全矩阵或生产“全功能无感”验收完成。v0.2.4 已发布，默认旧协议仍不自动切换；须保留实测记录、明确其他未测项，并在维护窗口逐整链确认迁移，不能自动重启既有客户节点。
