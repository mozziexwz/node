# 备份与恢复

日常整站备份使用安装菜单 8、9、13、14、15，操作方法见[在线整站备份](disaster-backup.md)。v2.0 使用系统 Caddy；无需停止共享反向代理，也不恢复或清理其他网站。

## 整站灾难恢复

1. 停用或隔离原 MSBOOST 面板，防止双站同时处理任务、支付和节点。
2. 把已验证备份放到新目标的 root 私有目录，使用与备份一致版本的官方安装入口，选择菜单 10。
3. 目标不得已有 MSBOOST 安装、专用数据卷或本站代理文件，但可以保留其他 Caddy 网站。
4. 工具验证备份后创建全新数据库，恢复业务、文章附件、原密钥及本站 Caddy 扩展。归档里的安装脚本和 Compose 文件不会被执行。
5. 共享 Caddyfile、共享证书和其他站点不被覆盖。本站证书由 Caddy 使用现有证书或重新签发。
6. 恢复后保持维护，支付与兑换关闭，旧会话和管理凭据失效。核对快照之后的账务，用菜单 16 重新连接捐赠节点；执行机重新关联。确认业务后再开放营业、设置自动备份。

完整恢复使用快照时间点的用户、枫叶、权益、订单、账本、流量和设置。快照之后的付款不会凭空找回，必须与支付平台核对；历史任务不自动重放。原主密钥丢失无法解密，不会生成替代密钥假装恢复成功。

v2.0 全新部署不提供旧 Docker Caddy 数据或旧备份迁移。旧备份应使用创建它的旧版工具在单独环境处理，不要将旧备份直接导入新版生产站点。

## 网页安全恢复不是财务回滚

网页上传的 `.msb` 用于安全合并设置、文章和允许恢复的配置；保留当前用户、密码、余额、权益、订单、账本和流量等关联业务，不替换成旧快照。正在使用的线路/节点不会被旧拓扑静默覆盖。

先开启维护，处理运行中的任务和规则，点击“只预检，不恢复”，按具体阻止项处理，再确认恢复。预检后数据变化会要求重新预检。恢复前必须成功生成私有回滚副本；恢复后旧会话和 Agent 凭据失效，保持维护直到完成核对。

## 失败处理

备份失败先看菜单 13；异地失败时本地成功包仍保留，可以修复连接后用菜单 15 重传。恢复失败保留 root 私有工作目录及导入记录，不要删除隔离标记或通过重建密钥绕过检查。

不要执行全局 Docker prune、`down -v`，不要删除 `/var/lib/caddy` 或整份 `/etc/caddy`。Caddy 为共享服务，其他网站的恢复应使用它们自己的备份方案。
